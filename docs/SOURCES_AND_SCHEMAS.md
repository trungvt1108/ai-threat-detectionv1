# Sources and schemas

## Registration

A source is a folder (`root_path`) plus a file-name pattern, a type, provenance, privacy class and
an optional timezone assumption. You register it via `manage.py register_source` or the
**Nguồn** page (admin only).

The root must be inside `ATD_ALLOWED_SOURCE_ROOTS`. By default these are `.local/inbox`,
`.local/lab` and `.local/datasets`. Every file request is resolved and checked again:

- it must be relative to the root;
- it cannot use `..`, absolute paths or symlink escapes;
- the name must match the pattern (or the rotation suffix `pattern.*`).

When no pattern is given, JSON types use `*.ndjson` and text types (`http_combined`,
`auth_syslog`) use `*`.

| Type | Domain | Format |
|---|---|---|
| `http_json` | HTTP | JSON / NDJSON access records |
| `http_combined` | HTTP | nginx / Apache "common" or "combined" text lines |
| `auth_json` | AUTH | JSON / NDJSON authentication records |
| `auth_syslog` | AUTH | sshd lines in `auth.log` / `secure` / `journalctl -o short-iso` |
| `suricata_eve` | EVE | Suricata EVE JSON, `alert` and `flow` only |

There is no API that reads arbitrary paths or URLs.

| Provenance | Meaning |
|---|---|
| `SYNTHETIC_DEMO` | Generated by `demo/synthetic.py` or hand-written fixtures |
| `LAB_OBSERVED` | Written by the project fixture service during a lab capture |
| `USER_IMPORTED` | Files you exported and imported |
| `PUBLIC_DATASET` | Licensed public data (none in v1) |
| `LIVE_FOLLOW` | A file followed while it is being written |

Replaying lab logs is not production monitoring. Privacy classes: `PRIVATE` (default for user
data), `LAB`, `DEMO`, `PUBLIC_LICENSED`.

## Canonical event (`sources.Event`)

| Group | Fields |
|---|---|
| Identity / location | `event_id` (deterministic), `namespace`, `source`, `source_type` |
| Schema | `schema_version` (`atd.http.v1` / `atd.auth.v1` / `atd.eve.v1`), `domain` |
| Time | `event_time` (UTC), `ingested_at` |
| Locator | `file_key` (first-line fingerprint), `offset`, `line_no` |
| Classification | `provenance`, `privacy_class` |
| Identities | `entity_key` / `user_key` / `host_key` (pseudonyms) |
| Content | `fields` (allowlisted values only), `quality_flags` |
| Bookkeeping | `capture_id` (experiments only), `excluded_from_windows` |

Rejected input is kept as locator + SHA-256 + reason, never the raw line. A scrubbed preview is
stored only if the source enables `store_invalid_preview`.

Reject reasons:

| Group | Reasons |
|---|---|
| Line level | `invalid_json`, `not_json_object`, `invalid_utf8`, `oversized_line`, `unrecognized_access_line`, `unrecognized_syslog_line` |
| Timestamp | `missing_timestamp`, `invalid_timestamp`, `missing_timezone`, `implausible_timestamp` |
| EVE | `unsupported_event_type`, `missing_event_type`, `alert_object_missing`, `flow_object_missing` |
| Array files | `json_array_too_large`, `invalid_json_array` |

**Skipped is not rejected.** Text adapters *skip* well-formed lines that are out of their scope,
for example cron or sudo lines in `auth.log`. Skips are counted per reason in `skipped` /
`skip_reasons` on the ingest run and shown on the source page. They do not count towards
`parse_failure_ratio` (HLTH-001).

## Timestamps

- Offset-aware ISO 8601 is accepted, including `Z` and Suricata's `+0000`.
- Numeric epoch seconds/ms are accepted (flag `epoch_ts`).
- Naive timestamps are **rejected** (`missing_timezone`) unless the source declares
  `assume_timezone`. With an assumption they are accepted and flagged `tz_assumed`, and the
  assumption is shown on the source page.
- Years outside 2000–2100 are rejected.
- Events more than 5 minutes in the future (wall clock) are stored with `future_timestamp` and
  excluded from windows and watermarks.

## HTTP access JSON/NDJSON (`http_json`, `atd.http.v1`)

| Input names (first match) | Stored as |
|---|---|
| `timestamp`, `time`, `@timestamp`, `ts` | `event_time` |
| `client_ip`, `remote_addr`, `client`, `src_ip`, `client_id` | `entity_key` (pseudonym `ip_…`) |
| `method`, `request_method` | `method` (known verb or `OTHER`) |
| `path`, `url`, `uri`, `request_uri` | `path` (normalized), `path_group`, `had_query`, `query_param_count` |
| `status`, `status_code` | `status` (100–599) |
| `bytes`, `response_bytes`, `body_bytes_sent`, `bytes_sent` | `bytes` |
| `duration_ms`, `request_time_ms`, `latency_ms` / `request_time`, `duration_s` (s → ms) | `duration_ms` |
| `sensor`, `server`, `host` | `sensor` (scrubbed, ≤ 64 chars) |

Path normalization:

- Scheme, host, userinfo, query string and fragment are removed.
- Identifier-like segments become `{num}`, `{uuid}`, `{hex}`, `{token}`, `{email}` or `{other}`.
- At most 12 segments are kept.

A missing status, bytes or duration stays `None` with a `missing_*` flag. It never becomes
200, 0 bytes or 0 ms.

## Authentication JSON/NDJSON (`auth_json`, `atd.auth.v1`)

| Input names | Stored as |
|---|---|
| time aliases as above | `event_time` |
| `src_ip`, `source_ip`, `client_ip`, `remote_addr`, `src`, `client_id` | `entity_key` |
| `user`, `username`, `account` | `user_key` (pseudonym `user_…`) |
| `host`, `hostname` | `host_key` (pseudonym) |
| `service`, `program`, `app` | `service` (short token) |
| `outcome`, `result`, `status` | `outcome` |
| `auth_method`, `method` | short token |
| `reason`, `failure_reason` | short token only; free text is dropped |

`outcome` values:

- `SUCCESS`: success / ok / accepted / true …
- `FAILURE`: failure / failed / denied / false …
- `UNKNOWN`: anything else
- `MISSING`: field absent

A missing outcome is never a success. Passwords, OTPs and tokens are never stored.

## HTTP access text (`http_combined`, `atd.http.v1`)

NCSA common / combined format, the default of nginx (`combined`) and Apache (`common`,
`combined`):

```
203.0.113.5 - - [28/Oct/2026:09:00:01 +0700] "GET /login?next=/a HTTP/1.1" 200 512 "-" "Mozilla/5.0"
```

| Part | Stored as |
|---|---|
| `%h` client | `entity_key` (pseudonym `ip_…`); `-` → `missing_entity` |
| `[%t]` | `event_time`. The format always carries an offset; month names are parsed locale-independently |
| `"%r"` request line | `method` (known verb or `OTHER`), normalized `path` like `http_json`. The protocol is dropped. An empty or binary request line (TLS probe, scanner) → `method=OTHER`, flag `malformed_request_line` |
| `%>s` | `status` (100–599) |
| `%b` | `bytes`; `-` means 0 bytes, as defined by the format |
| trailing `rt=<s>` or `request_time=<s>` | `duration_ms` (optional; add `rt=$request_time` to the nginx `log_format` to get it) |
| `%l`, `%u` (remote user), referer, user agent, other trailing fields | dropped |

Without a duration, the `http_v1` feature set abstains. Train such sources with
`http_v1_core` (see FEATURE_SPEC). Rules work either way.

## SSH authentication text (`auth_syslog`, `atd.auth.v1`)

Reads sshd decisions from syslog text. Two prefixes are accepted:

```
2026-10-28T09:00:01.123456+07:00 web1 sshd[812]: Failed password for invalid user admin from 203.0.113.5 port 52314 ssh2
Oct 28 09:00:01 web1 sshd[812]: Accepted publickey for alice from 198.51.100.7 port 50022 ssh2
```

- **RFC 3339** (rsyslog high-precision format, the Ubuntu 24.04+ default, `journalctl -o short-iso`):
  the offset is used. Fractions beyond microseconds are truncated.
- **Traditional BSD syslog** (`Mon dd HH:MM:SS`, no year, no zone): requires the source's
  `assume_timezone`, otherwise `missing_timezone`. The year is inferred from the ingest time (the
  previous year if the date would be more than a day in the future) and flagged `year_inferred`
  and `tz_assumed`.

| Line | Result |
|---|---|
| `sshd` / `sshd-session` / `sshd-auth`: `Accepted <method> for <user> from <ip> port …` | event, `outcome=SUCCESS` |
| same programs: `Failed <method> for [invalid user ]<user> from <ip> port …` | event, `outcome=FAILURE`, `reason` = `invalid_user` or `invalid_credentials` |
| `message repeated N times: [ <one of the above> ]` | one event, flag `repeated_message_collapsed` (the N repeats cannot be recovered as separate events) |
| `Invalid user X from …` | skipped (`invalid_user_notice`): OpenSSH logs a `Failed … for invalid user X` line for the same attempt when a credential is tried |
| other sshd messages (connect, disconnect, PAM) | skipped (`sshd_other_message`) |
| other programs (cron, sudo, systemd, …) | skipped (`not_sshd`) |
| anything that is not a syslog line | rejected (`unrecognized_syslog_line`) |

`service` is `sshd`, `auth_method` is the method token (`password`, `publickey`,
`keyboard-interactive-pam`, …). User, source IP and syslog host are pseudonymized. Only these
fields are kept.

## Suricata EVE (`suricata_eve`, `atd.eve.v1`)

The field subset follows the Suricata **7.0.x** EVE format documentation (common fields + `alert`
+ `flow`). The same names exist in 6.0.x. Other event types are counted as
`unsupported_event_type`. Do not assume newer or older formats match without testing a sample.

| Kept | Dropped |
|---|---|
| `event_type`, sensor (`host`), `flow_id` + `correlation_key = sensor:flow_id`, `in_iface`, `proto`, `app_proto`, `community_id`, ports, `src_ip`/`dest_ip` (pseudonyms) | `payload`, `payload_printable`, `packet`, `http`, `tls`, `files`, `metadata` and all other objects |
| `alert.{action,gid,signature_id,rev,signature (scrubbed),category,severity}` | |
| `flow.{pkts_*,bytes_*,start,end,age,state,reason,alerted}` | |

Scope rules:

- EVE `alert` events become `UPSTREAM_IDS` alerts, clearly marked as Suricata signals and not as
  this project's detections.
- No EVE field (alert flag, signature or severity) is used as an ML feature or as a label for
  evaluating the project's detectors.
- `flow` events have no features or model in v1. Their status is **UPSTREAM_ONLY**.
- Correlation is only "same IP pseudonym within ±10 minutes", shown with the sensor name.
  `flow_id` is never assumed to match across sensors or sources.

### Importing EVE from your own lab (manual, nothing is installed or connected automatically)

1. On the lab machine, export the relevant `eve.json` slice yourself (for example with `jq`, keeping
   only `alert`/`flow` events). Copy it to `.local/inbox/<lab-name>/` on this machine.
2. Run:

   ```
   python manage.py register_source --name <lab-name> --type suricata_eve --root .local/inbox/<lab-name> --pattern "*.json" --privacy-class PRIVATE --provenance USER_IMPORTED --sensor <sensor-name>
   python manage.py import_logs --source <lab-name> --file eve.json
   ```

3. Check the source page for `unsupported_event_type` counts and the Suricata version note.

## Import modes

| Mode | Command | Semantics |
|---|---|---|
| Batch import | `import_logs` | Chunked, resumes from checkpoint, re-import adds 0, `--from-start` de-duplicates. A final unterminated line is imported only if it parses (flag `no_trailing_newline`); otherwise it is counted as `partial_pending` and left for the next run |
| Replay | `replay_logs` | File order into `replay:<name>`. Logical event clock; detection runs after every chunk with watermark = clock. `--speed N` sleeps (gap/N, capped at 2 s) |
| Follow | `follow_source` | Bounded duration. Waits for complete lines. Rotation: drains the old file found by fingerprint among `name.*` siblings, otherwise notes `rotation_old_file_not_found_possible_data_loss`. Truncation resets the offset and is noted. Missing file / permission denied go to source health. Stale data raises HLTH-002 |

Late events, meaning events whose window was already closed by the watermark, are stored with
`late_after_window_close`, counted, and **not** merged into historical windows.

Known limitation: two different files whose first line is byte-identical share a `file_key`. Real
logs with timestamps make this unlikely.
